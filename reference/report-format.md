# 報告書格式（計畫書草稿輸出規範）

> 本檔規範 `drafts/<計畫資料夾>/` 內計畫書草稿的**輸出格式**，由 `CLAUDE.md` 以引用方式指向。此處只談「草稿長什麼樣子」；計畫書的章節內容與審查邏輯依 `tpr-guiding-principle/附件1_計畫書格式_結構化.md`，這份計畫的題目與設定依該計畫資料夾的 `PROJECT.md`。

## 一、內文段落規則（最重要）

計畫書內文格式單純，一段文字就是一段，不要隨意分行。撰寫 Markdown 草稿時，同一段落的文字寫成**單一行**（不在段落中間手動換行、不硬性斷到固定欄寬），段落與段落之間以一個空行分隔，換行交給編輯器的自動軟換行處理。這樣可避免草稿看起來被切成許多短行，也方便日後複製到 Word 時維持完整段落。

## 二、標題與章節結構

草稿的標題階層對應 `附件1_計畫書格式_結構化.md` 區塊二「計畫書內容結構」的本文八項：動機、研究主題與目的、文獻探討、教學設計與規劃、研究設計與執行規劃、預期完成工作項目與成果、參考文獻、附件。標題用 Markdown 的 `#`／`##`／`###`，不在標題文字內手動編號以外再加多餘符號。

## 三、表格、清單與圖

- 表格用於欄位對照、變數整理、進度對應等結構化資訊；一般論述仍以段落為主，不要用清單取代必要的說明段落。
- 清單（`-` 或數字）用於並列項目，清單項下若需說明，補一段文字，不要只留標題式短語。
- 需要流程圖或關係圖時，可用 Mermaid 區塊；圖僅作輔助說明，不作裝飾。

## 四、佔位與待補標示

尚無真實資料或需另行發展的部分，一律以 `〔待補〕` 或 `〔待補：說明〕` 明確標示，不得捏造個人經歷、數據或引用。缺漏處、待決策與待釐清事項集中整理於計畫資料夾的 `MEMO.md`，不在草稿末附「待補清單」，也不在草稿內寫長段註記；草稿內的標記需要說明時，寫「見 `MEMO.md` 某項」。

需要文獻支撐、但素材裡沒有來源的句子，標 `〔TODO(cite)：要補什麼〕`；有大致印象、但作者、年份或出處未經核實的文獻，標 `〔TODO(confirm)：要確認什麼〕`。兩種標記都要在冒號後寫清楚要補什麼，定稿前必須清空。

## 五、中文排版

遵循全域排版規範：中文標點用全形，數字、英文與程式碼識別字用半形，中英文之間、中文與數字之間加一個半形空格。程式碼區塊、檔名、路徑、URL 內不套用此規則。

## 六、定稿體例（轉 Word／PDF 時套用）

草稿為 Markdown，供閱讀與修訂；最終上傳須依 `附件1` 區塊一轉為 Word／PDF 定稿，體例如下：

| 項目 | 規範 |
|---|---|
| 字體 | 中文標楷體、英文 Times New Roman、12 pt |
| 行距／間距 | 單行間距、標準字元間距 |
| 邊界／頁碼 | 上下左右各 2 cm；頁碼置於每頁下方中央 |
| 頁數上限 | 一年期至多 25 頁、多年期至多 40 頁（含參考文獻、附件，不含封面） |
| 主持人部分 | 至多 5 頁 |
| 上傳格式 | 計畫內容含封面轉 PDF（≤ 30 MB）；授課計畫書另附 PDF（≤ 1 MB） |

這些體例限制在草稿階段只作備忘，不在 Markdown 內套版。
