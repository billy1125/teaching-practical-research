# 段落編修（繁體中文，套用個人筆法）

本技能負責**套用** `writing-style/personal-voice.md` 的作者筆法去改稿，不負責產生或修改 `personal-voice.md` 本身。

## 一、硬界線（先讀這段）

編修只動語言表層。下列事項一律不做，遇到時標記出來交給使用者，不自行處理：

- **不更動論證**：不改變主張、不調整推論順序、不新增或刪除理由、不強化或弱化結論。
- **不新增事實**：不補文獻、不補數據、不補例子、不補作者沒寫過的教學現場細節。素材沒有的東西，編修階段也不能長出來。
- **不改引用**：行內引用的作者、年份、格式一字不動。引用格式有問題時標出位置，交給使用者處理。
- **不清除待補標記**：`〔待補〕`、`〔TODO(cite)：…〕`、`〔TODO(confirm)：…〕` 原樣保留。
- **不刪必要內容**：不因為「改起來比較順」就刪掉 `tpr-guiding-principle/附件1_計畫書格式_結構化.md` 要求的內容。
- **不順手重構結構**：不合併或拆分 `##`／`###` 章節，不搬動段落到別節。

**主張強度是灰色地帶**：把「顯著提升」改成「提升」會改變宣稱強度，屬於論證層面，不在編修範圍。`personal-voice.md` §7 的主張強度規則只在**同強度的不同說法之間**選擇（例如「資料顯示」與「分析顯示」），不能拿來調整強度本身。

## 二、輸入

| 來源 | 用途 | 缺少時 |
| --- | --- | --- |
| `writing-style/personal-voice.md` | 筆法規則的主要依據 | 見第三節「三層遞退」 |
| `reference/report-format.md` | 段落單行、標題階層、待補標示、中文排版 | 必讀，不可略過 |
| `reference/academic.md` | 學術寫作的認識論標示與論證要求 | 必讀 |
| 待編修的草稿檔 | 編修對象 | 使用者指定 |

## 三、無 `personal-voice.md` 時的三層遞退

1. 有 `writing-style/personal-voice.md` → 直接套用作者筆法。
2. 沒有 → **先提醒使用者**可提供 `writing-style/personal-voice.md`，或確認是否要套用個人筆法。
3. 使用者仍未指定 → 以通用標準學術中文編修，並在回報時明說用的是通用筆法而非作者筆法。

不得在沒有 `personal-voice.md` 的情況下，憑對作者的印象「猜」筆法。

## 四、工作單位

一次編修**一個 `##` 章節區塊**，不一次掃全篇。理由是編修的品質隨區塊長度下降，而且一次改一節時 git diff 讀得懂、改壞了容易退回。

使用者指定「改第五節」時，就只讀那一節與必要的前後文（前一節末段、後一節首段，用來判斷銜接），不動其他章節。

## 五、編修流程

1. **讀規則**：`personal-voice.md`（§1～§7 為主）、`report-format.md`、`academic.md`。
2. **讀目標區塊**：整段讀完再動手，不邊讀邊改。先判斷這一節在整篇中承擔什麼功能（動機？方法？成果？），功能決定語氣與句長的取捨。
3. **逐段編修**，依下列優先順序處理，前面的問題優先於後面的：

   | 順序 | 檢查項 | 依據 |
   | ---: | --- | --- |
   | 1 | 排版硬規則：同段落是否寫成單一行、段落間是否空行分隔 | `report-format.md` |
   | 2 | 中文排版：全形標點、中英數之間半形空格、括號全半形 | `report-format.md` |
   | 3 | 句長與句構：過長的複合句拆開，一句講一件事 | `personal-voice.md` §3 |
   | 4 | 連接與過渡：換成作者慣用的銜接詞，去掉文言腔 | `personal-voice.md` §4 |
   | 5 | 用詞：套用偏好詞、換掉避免詞 | `personal-voice.md` §5 |
   | 6 | 人稱與立場：統一自稱與敘述立場 | `personal-voice.md` §2 |
   | 7 | 術語一致性：同一概念全篇同一名稱；專有名詞首次出現寫全名與說明 | `academic.md` |
   | 8 | 段落銜接：段首是否接得上前段的結尾 | `personal-voice.md` §4 |

4. **回頭校一次**：改完再讀一遍，確認論證沒有在改寫中被動到。這一步是本技能唯一不能省的步驟。
5. **直接改檔**，不另存新檔，diff 交給 git。

## 六、輸出

改完之後回報三件事，各一段，不要長篇說明：

1. **這一節改了什麼**：以類型歸納（例如「拆長句 6 處、統一術語 2 組、補中英文空格 14 處」），不逐句列。
2. **標記給使用者的項目**：碰到硬界線而沒有處理的地方，附位置與原因。
3. **判斷不了的地方**：語意兩可、不確定作者原意的句子，原樣保留並列出。

不要在回報中重述原文，也不要解釋每一處改動的理由——理由寫在 `personal-voice.md` 裡，讀者要看自己會去看。

## 七、常見誤區

- **把編修做成重寫**：整段換句話說，讀起來更順但論證變了。編修的成功標準是「作者認得出這是自己寫的，只是更順」，不是「文字更漂亮」。
- **過度統一**：不同章節本來就該有語氣差異（動機偏敘事、方法偏規格）。`personal-voice.md` 的規則是傾向，不是要把全篇壓成同一種調。
- **刪掉「囉唆」的限制條件**：學術寫作裡的「在本研究的樣本範圍內」「僅為探索性分析」不是贅字，是誠實揭露，刪了就變成過度宣稱。
- **順手修正事實**：看到疑似錯誤的年份、數據、名稱，標出來，不要直接改。
