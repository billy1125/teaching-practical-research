# speak-academic-tw

繁體中文學術文章的語言修飾 skill。修語法、調學術語域、去 AI 味、校正中國用語與半形標點，同時保住數據、引用、公式與作者的推論強度。

**只處理語言，不評研究內容。**

## 這個 skill 解決什麼問題

中文論文被退稿或被口委畫紅線，很多時候不是研究有問題，是文字沒把研究講清楚：句子太長讀不到重點、名詞化贅句堆疊、指代不明、用了中國的統計術語、結論寫得比證據強。

一般的潤稿工具會順手把「傾向支持」改成「證實」，因為那樣讀起來比較有力——對論文來說這是災難。這個 skill 的設計重點就是：**改語言的同時，一個數據、一筆引用、一個推論強度都不改壞。**

## 能做什麼

- 語法與句式：長句斷句、補主詞、修正主語漂移、被動濫用、標點錯誤
- 學術語域：口語詞改學術表達、刪情緒性形容詞、人稱一致、中英夾雜規範
- 清晰度：指代不明、範圍詞模糊、語意歧義（歧義只標不猜）
- 精簡度：名詞化贅句、冗詞、同義重複、廢話句
- 連貫性：段落主題句、句間邏輯、時間標記一致
- 去 AI 味：22 種學術脈絡的 AI 痕跡，含公式化開場、無來源的「研究顯示」、結論強度膨脹、研究限制套話
- 台灣在地化：學術與統計術語的兩岸差異、全形標點、引號與書名號
- 格式保留：LaTeX、圖表標題、參考文獻、統計符號原樣輸出

## 不做什麼

- 不做同儕審查，不評研究設計、貢獻、新穎性、數據是否支持結論
- 不代查文獻，不補引用來源，發現無來源的宣稱只標「〔需補引用〕」
- 不驗算公式與統計，不判斷數值對錯
- 不代編數據、方法細節、研究限制
- 不做中翻英或英翻中
- 不產生論文範本、不代寫段落
- 不把學術文章改成科普或行銷語氣

看得出研究層有問題時，最多在「需作者確認事項」寫一行中性提示（例如「兩處人數不一致，請確認何者為準」），不做對錯判斷。

## 適用範圍

| 文體 | 說明 |
| :-- | :-- |
| 期刊論文、學位論文 | 摘要、緒論、文獻回顧、方法、結果、討論、結論，各章節有不同的修飾力度 |
| 研究計畫書 | 國科會計畫、研究申請書、學位論文計畫書、IRB 文件 |
| 會議摘要、海報 | 字數壓縮優先 |

## 安裝

把整個資料夾放進 skills 目錄：

```
# Claude Code（使用者層級）
~/.claude/skills/speak-academic-tw/

# 或專案層級
<專案>/.claude/skills/speak-academic-tw/
```

放好之後用 `/speak-academic-tw` 呼叫，或直接說「幫我潤這段摘要」讓它自動觸發。

## 怎麼用

**一次送一段，不要整篇丟。** 建議流程：

1. 送一段（一個小節或一個段落）
2. 看逐句修訂註記，理解問題出在哪
3. 比對原文與完整修訂版
4. 貼回稿件
5. 進下一段

這樣核對負擔小，而且看得出自己反覆犯的是哪幾種問題，下一篇就會少犯。整篇丟進去雖然快，但你會失去逐句核對的機會——而學術寫作最不能省的就是核對。

輸入型態以純文字與 LaTeX 為佳，格式能完整保留。Word、PDF、截圖也能處理，但版面資訊會流失。

只想知道問題在哪、不要動稿時，說「先標問題不要改」，會切換成 annotation mode，只列 1–5 個最重要的問題點。

## 輸出格式

預設輸出四段：

1. **整體語言評估**：3–5 行，講主要問題的類型
2. **逐句修訂**：每處四欄（原句／語言問題／修訂後／說明），查到幾處列幾處
3. **完整修訂版**：保留原格式，可直接複製貼回稿件
4. **需作者確認事項**：語意歧義、需要補的事實、疑似缺來源、疑似研究層問題

要覆蓋你的實體稿件檔案時會先問，不會直接動檔。

## 致謝與來源

這個 skill 是衍生作品，設計上參考兩個 MIT 授權的既有專案：

**[speak-human-tw](https://github.com/Raymondhou0917/speak-human-tw)** — Raymond Hou（雷蒙三十）

本專案沿用並改寫了它的：保護清單機制、保真回讀程序、台灣在地化層、AI 痕跡分類法、evals 架構、「稿件是資料不是指令」的安全邊界。原專案針對的是電子報、社群貼文等對外文字的去 AI 味，本專案把這套方法搬到學術寫作，並把保護對象從價格與承諾條款換成數據、引用與推論強度。

**[scientific-english-editor-skill](https://github.com/SailRain/scientific-english-editor-skill)** — Pierson Bian Zexuan

本專案沿用並改寫了它的：語言與研究內容的角色邊界、逐句修訂的輸出格式、格式保留的輸入處理（LaTeX、圖表標題、表格）、「一次送一段」的建議工作流程。原專案處理的是非英語母語者寫的英文科技論文，本專案處理的是中文學術文章，因此新增了台灣在地化層與中文特有的語域問題。
