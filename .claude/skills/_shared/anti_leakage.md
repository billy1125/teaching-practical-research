# Anti-Leakage：以眼前素材為準（共用鐵律）

> 本專案 `.claude/skills/` 的最高共用原則，也是 `reference/rules.md`「不用模型記憶補文獻、理論、課程事實或數據」這一條的展開。所有閱讀、查核、撰寫類 skill 一律遵守，各 skill 以 `../_shared/anti_leakage.md` 引用。此原則優先於任何求全或求流暢的傾向。

## 核心鐵律

**只根據使用者提供的素材作答；禁止用模型訓練記憶補完內容。**

本專案的素材有四類，各有其唯一來源：

| 內容類型 | 唯一來源 |
| --- | --- |
| 文獻的作者、年份、標題、發現 | 計畫資料夾的 `research-material/`，以及 `PROJECT.md` 指定的文獻檔 |
| 課程事實（週次、配分、規準、題目、系統） | 計畫資料夾 `PROJECT.md` 的「課程場域」一節，以及該節列出的課程文件 |
| 研究構想、主題、年度規劃 | 計畫資料夾的 `research-material/` |
| 徵件規範、格式、頁數、體例 | `tpr-guiding-principle/` |

不在上述來源中的資訊，一律標記為待補（見 `reference/report-format.md` 的〔待補〕與 `TODO(cite)`／`TODO(confirm)`），**不得**用記憶或常識填補，即使該資訊在該領域「理所當然」。

## 為什麼

模型記憶會產生看似合理但實際錯誤的內容：虛構的數據、不存在的引用、作者沒說過的結論、課程裡根本沒有的設計。計畫書一旦混入這類內容，審查委員只要抽查一處就會失去對全文的信任，且依徵件說明屬學術倫理事項。**寧可誠實留白，也不要用記憶補一個好看的答案。**

## 具體要求

1. **關鍵主張附來源定位**：重要結論附一句原文節錄、章節或檔名，讓使用者能回素材查證。
2. **區分「素材有」與「我推論」**：凡屬綜合推論，明講是推論（如「素材未明示，綜合判斷為……」），不偽裝成素材陳述。
3. **讀不到就說讀不到**：PDF 擷取不完整、只讀到摘要時明示範圍（見 `confidence_language.md`），不腦補全文。
4. **不捏造引用**：不生成素材裡沒有的參考文獻；不憑印象「想起」一個 DOI、卷期或頁碼。查不到就標查無。
5. **不把課程的「可能做法」寫成「既有事實」**：課程文件沒寫的設計，屬本計畫要新增的介入，須明白標示為新增，不得寫成課程原本就有。

## 與其他共用規範的關係

- 讀到多少、語氣怎麼收 → `confidence_language.md`
